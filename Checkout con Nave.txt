Checkout con Nave
Integrá nuestra solución de cobros vía API y permití pagos con QR o tarjetas directamente desde tu sitio o app. Vas a tener una experiencia simple y segura para tus clientes.
¿Qué necesitás para empezar?

    Credenciales de sandbox y producción: te permiten generar un token de acceso para comunicarte con nuestras APIs.
    Utilizar nuestras APIs: para generar intenciones de pago en tiempo real.
    Elegir cómo mostrar el proceso de pago: podés renderizar un QR, embeber el SDK o redirigir al usuario a nuestro checkout. 

Ciclo de vida de un pago
Conocé el flujo completo desde la autenticación hasta la acreditación:

    Obtener un access_token con nuestro servicio de autenticación.
    Generar una intención de pago.
    Redireccionar al usuario al checkout_url o renderizar el QR.
    Recibir notificaciones de estado de pago en tiempo real.

Ciclo de vida de un pago
Autenticación
Para poder generar y enviarte tus credenciales, necesitamos que nos compartas la siguiente información:

    CUIT del comercio
    Dos URLs de notificación (notification_url):
        Una para el entorno de sandbox, donde recibirás notificaciones de prueba.
        Otra para el entorno de producción, donde recibirás las notificaciones de pagos reales en tiempo real. 

Además, es necesario que completes el flujo de alta de tu nuevo punto de venta online desde la plataforma Nave:

    Ingresá a Nave > Integraciones > Tienda Online Propia
    Completá el proceso de vinculación
    Al finalizar, vas a recibir un código de vinculación

👉 Recordá que las credenciales de sandbox y de producción son diferentes, por lo que recibirás un set para cada entorno.📩 Envianos toda la información solicitada junto con el código de vinculación a través de tu ejecutivo Galicia o escribinos a integraciones@navenegocios.com.

Redireccionar al Checkout
Podés crear un botón de pago y redireccionar a nuestra URL para procesar el pago.
Experiencia de pago

    En desktop se muestra un QR para escanear con billetera virtual o banco. Si el ingreso manual de tarjetas se encuentra habilitado, puede completarse el pago ingresando datos manuales.
    En mobile se redirige automáticamente a MODO y el usuario puede elegir si pagar desde la APP de MODO o APP bancarias.

Notificación de un pago
Nave enviará un POST con la notificación del evento de pago a tu endpoint configurado cada vez que el pago asociado a una intención de pago cambie de estado. Esto te permitirá mantener actualizado el estado de tus órdenes en tiempo real (ej. de PENDING a APPROVED, de APPROVED a REFUNDED, etc.).

Estados posibles de un pago
Diagrama de estados de un pago
Estado 	Descripción
PENDING 	Transacción iniciada, sin resultado final
APPROVED 	Pago aprobado
REJECTED 	Pago rechazado
CANCELLED 	Cancelación manual antes del cierre del lote
REFUNDED 	Devolución total emitida
PURCHASE_REVERSED 	Reversado antes de liquidarse
CHARGEBACK_REVIEW 	Disputa en proceso por contracargo
CHARGED_BACK 	Contracargo confirmado por la entidad emisora

Estados de pago cancelados
Diagrama de estados de pago cancelado
Proceso de cancelación
Cuando se solicita la cancelación de un pago, el endpoint devuelve inicialmente el estado CANCELLING, lo que indica que el proceso está en curso.
Este estado no significa que el pago ya fue cancelado.
Notificación de estado final
Una vez que la cancelación se procesa, recibirás una notificación con el estado definitivo del pago, que puede ser:
Estado 	Descripción
CANCELLED 	El pago fue cancelado exitosamente.
REFUNDED 	El pago fue reembolsado exitosamente
Si ocurre un error durante la cancelación, el sistema devolverá el estado APPROVED, que corresponde al estado original en el que se encontraba el pago antes de intentar la cancelación. Este comportamiento busca evitar confusiones sobre el estado real del pago mientras se procesa la cancelación.
